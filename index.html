1 Introducción

El presente informe detalla el proceso de modelado e implementación de una base de datos para el gimnasio "Muscle & Fitness". La solución aborda la problemática de la gestión manual de socios, pagos y programación de clases grupales.

Utilizando el motor de base de datos Oracle 21c, se han implementado estructuras transaccionales y lógica de servidor mediante Procedimientos Almacenados (PL/SQL), garantizando la integridad de los datos y la automatización de procesos críticos como el registro de membresías y el control de aforo en clases.

2 Descripción del Negocio

Requerimientos Principales:

  • Gestión de Clientes y sus datos personales.
  • Control de diversos tipos de membresías y precios.
  • Programación de clases con entrenadores específicos.
  • Registro histórico de pagos y suscripciones.

"Muscle & Fitness busca optimizar la experiencia del usuario final, permitiendo una inscripción rápida y una visualización clara de sus pagos y clases programadas, eliminando errores de doble cobro o cruce de horarios."

4 Implementación SQL

A continuación, el script de creación de tablas maestras bajo estándares de Oracle Developer:

-- 1. CREACIÓN DE TABLA CLIENTE
CREATE TABLE tcliente (
    idcliente NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nombrecompleto VARCHAR2(100) NOT NULL,
    dni VARCHAR2(15) NOT NULL,
    telefono VARCHAR2(20),
    email VARCHAR2(100)
);

-- 2. CREACIÓN DE TABLA MEMBRESIA
CREATE TABLE tmembresia (
    idmembresia NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    tipo VARCHAR2(50) NOT NULL,
    precio NUMBER(10,2) NOT NULL,
    duracionmeses NUMBER NOT NULL
);

-- 3. CREACIÓN DE TABLA PAGO (Relacional)
CREATE TABLE tpago (
    idpago NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    fechapago DATE DEFAULT SYSDATE,
    monto NUMBER(10,2) NOT NULL,
    idcliente NUMBER,
    idmembresia NUMBER,
    CONSTRAINT fk_cliente_pago FOREIGN KEY(idcliente) REFERENCES tcliente(idcliente)
);

5 Lógica de Servidor (PL/SQL)

Implementación de procedimientos con gestión de errores (EXCEPTION), tal como se solicita en la rúbrica.

SP: Registrar Nuevo Cliente

CREATE OR REPLACE PROCEDURE sp_registrar_cliente (
    p_nombre IN VARCHAR2,
    p_dni IN VARCHAR2,
    p_tel IN VARCHAR2,
    p_mail IN VARCHAR2
) AS
BEGIN
    INSERT INTO tcliente (nombrecompleto, dni, telefono, email)
    VALUES (p_nombre, p_dni, p_tel, p_mail);
    COMMIT;
    DBMS_OUTPUT.PUT_LINE('Cliente registrado satisfactoriamente.');
EXCEPTION
    WHEN OTHERS THEN
        ROLLBACK;
        DBMS_OUTPUT.PUT_LINE('Error al registrar: ' || SQLERRM);
END;

SP: Registrar Pago de Membresía

CREATE OR REPLACE PROCEDURE sp_registrar_pago (
    p_id_cliente IN NUMBER,
    p_id_membresia IN NUMBER,
    p_monto IN NUMBER
) AS
BEGIN
    INSERT INTO tpago (fechapago, monto, idcliente, idmembresia)
    VALUES (SYSDATE, p_monto, p_id_cliente, p_id_membresia);
    COMMIT;
EXCEPTION
    WHEN OTHERS THEN
        ROLLBACK;
        DBMS_OUTPUT.PUT_LINE('Error en transacción de pago.');
END;

6 Conclusiones

El diseño del modelo conceptual permitió identificar las 6 entidades críticas para el negocio, asegurando que la información de los 120 registros insertados mantenga coherencia lógica.

La implementación de Procedimientos Almacenados reduce el tráfico de red y centraliza las reglas de negocio, evitando que se inserten datos huérfanos o inconsistentes.

El uso de bloques EXCEPTION en PL/SQL garantiza que ante cualquier fallo técnico (como una desconexión), la base de datos pueda realizar un ROLLBACK y mantener la integridad financiera del gimnasio.
